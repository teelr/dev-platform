| 2026-05-11 | When /review surfaces "inconsistent X across N files," the answer isn't always "align them." | 2026-05-11 | Synthetic test fixtures must use PAST timestamps. v0.5 Phase 3's /test built an end-to-end fixture covering every metric path — initially using timestamps like `2026-05-11T09:00:00` while current local time was ~05:00. The aggregator's window filter (`ts > until`, where `until = now`) silently dropped all 12 fixture events. Surfaced as "event_count = 0" in the first assertion. Fix: backdate fixture timestamps (e.g., `2026-05-10T...`) so they fall inside any reasonable `--period` window. Pattern: when writing time-bounded test fixtures, anchor timestamps to a known-past date (or compute relative to "now" minus an offset); never use today-but-future times. The aggregator's `--period all` does NOT mean "ignore the upper bound" — it means `since=datetime.min`, but `until` is always `now`. | dev-platform | active |
| 2026-05-11 | Spec-faithful implementation can ship inconsistencies inherited from the spec itself. v0.5 Phase 3's /review flagged two cross-metric naming/structural inconsistencies (`code_invocations` vs `count`; `events_per_project` inline vs as a metric_* helper) — BOTH of which were literally what the spec prescribed. | 2026-05-11 | Mock-binary pattern for testability — when a script depends on an external command (`code`, `python`, `docker`), the round-trip tests need to exercise the command's behavior without touching the live system. v0.6 introduced `tests/vscode/fixtures/mock-bin/code` — an extension-less Bash script that mimics `code --list-extensions` and `code --install-extension` via a `MOCK_STATE_FILE` env var. | 2026-05-11 | Negative-test fixtures must assert on the SPECIFIC failure cause, not just exit nonzero. v0.7 Phase 1's first cut of `tests/taxonomy/run.sh` asserted only `expected_exit==1` on `bad-roadmap-{sprint,rprefix}.md`. | 2026-05-11 | GitHub Actions reusable-workflow checkout MUST use `github.workflow_sha`, NOT `github.workflow_ref`. v0.7 Phase 2's spec prescribed `ref: ${{ github.workflow_ref \|\| 'main' }}` for the dev-platform self-checkout inside `taxonomy-check.yml`. | 2026-05-11 | Detection patterns for "old text" must not self-referentially match documentation about that old text. v0.9 Phase 2's `audit-project-drift.sh` initially used `grep -qE "/code → /test\|/test → /review"` to detect old workflow chain lines. | 2026-05-11 | Fixture subdirectories under `tests/<suite>/fixtures/` MUST avoid both (a) directory names that collide with repo-wide gitignore patterns and (b) runnable `.sh` files that the gate orchestrator could pick up as test runners. v0.8 Phase 1 hit BOTH simultaneously: spec said `tests/fleet-gate/fixtures/projects/{pass-1,...}/gate.sh`, but `.gitignore:132 projects/` is an unanchored exclude (matches `projects/` anywhere in the tree, beats the earlier `!tests/**/*.sh` re-include by rule-order); AND `scripts/gate_fast.sh`'s find walked `tests/<suite>/**/*.sh` and would have executed each mock gate as a test runner (one would fail, one would sleep 999s and hang the entire gate). | 2026-05-11 | When introducing a new `gh` (or any third-party CLI) invocation, smoke-test against the LOCALLY-INSTALLED CLI version before shipping. | 2026-05-11 | When a script has N modes (dry-run/apply) × M state combinations (target-exists / target-absent / disabled / missing-prereq), the test suite must exercise the CROSS PRODUCT, not just each axis once. v0.8 Phase 3's first cut had assertions for: dry-run with absent target (Check 6), --apply with absent (Check 7), --apply with existing (Check 8). | 2026-05-11 | Regexes that extract from multi-line text files MUST be anchored to line start (`^\s*` + `re.MULTILINE`) when the file is a structured format with comments. v0.8 Phase 4's `USES_RE` started as `r"uses:\s+teelr/dev-platform/[^@]+@(\S+)"` — unanchored. `re.search` returns the FIRST match, so a YAML comment containing `# uses: ...@v0.5` would shadow the real `uses: ...@v0.8` directive on the next line. Currently latent (source template has no such comment) but one template edit away from misclassifying every consumer. /review caught it; fix was `r"^\s*uses:\s+teelr/dev-platform/[^@]+@(\S+)"` + `re.MULTILINE`. The test fixture (`commented-uses-1` mock with the shadow comment present) was added in the same fix so the bug class can't recur silently. Pattern: when extracting from YAML / TOML / INI / Python / any commentable format, ALWAYS anchor the regex at start-of-line. Unanchored regexes treat every line uniformly, which is wrong for any format where comments and code coexist. | dev-platform | active |
| 2026-05-11 | String args that drive comparison logic MUST be validated at the argparse boundary; silent degradation on malformed input is the failure mode worth designing out. v0.8 Phase 4's `--latest <vX.Y>` flag accepted any string — so `--latest 0.7` (missing the `v` prefix) silently degraded every project to "up-to-date" because `parse_semver_minor` returned `None` and `classify` short-circuited. The user sees "everything fine" when the comparison axis was actually broken. | 2026-08-04 | `gh pr merge --delete-branch` HARD-FAILS the whole command when run from inside a git worktree — not a benign warning, as `commands/merge.md` incorrectly claimed.
