# v1.24 Shipped Directory — planning.md stops being a per-phase append target

v1.24 Shipped Directory, **closes v1.24** (2026-09-03, `tasks/shipped-directory-spec.md`): `planning.md` was the last per-phase append collision in dev-platform's own docs — every `/code` turn prepended a bullet to its "Recently shipped" section AND rewrote the "Active spec"/"Active Roadmap Phase" lines, so two concurrent sessions collided on both, exactly as they did on `tasks/lessons.md` before v1.23. The file was also chronically stale by neglect: its "In flight" section still opened with "v1.17 shipped", six phases behind, flagged twice and never fixed because nothing owned it. The fix is the v1.23 pattern taken one step further: each shipped phase becomes its own file, `tasks/shipped/<date>-v<X.Y>-<slug>.md` (phase filenames cannot collide — versions are claimed atomically, v1.11), chores get `<date>-<slug>.md`, and **`/code` stops editing `planning.md` entirely** — it is now a ~22-line static orientation doc, and the perpetually stale "In flight" section is deleted rather than fixed, since it only existed because something had to be hand-rewritten every phase. Zero-touch is the point: a small per-phase "Active" line edit would still conflict on every concurrent pair, and `/plan`'s existing fallback to `ROADMAP.md`'s highest version entry makes zero-touch free (that derivation is now inverted to prefer ROADMAP.md, which the claim script itself reads from `origin/main`). All five command changes are **convention-detected** on `test -d tasks/shipped`, like worktree mode — consumer projects keep their current `planning.md` behavior verbatim until they migrate from their own sessions with the committed `scripts/migrate-shipped.sh` (dry-run default, abort-not-skip on any unparseable or dateless bullet, v1.23's contract). `/merge`'s Change Summary Tier 1 becomes "read the shipped file this merge added", with the `planning.md` diff kept as the legacy fallback. Migration: 36 phase bullets + 14 chore bullets + the preamble, all verified mechanically — 50/50 bodies verbatim in exactly one file each, the pipe-bearing prose intact. `ROADMAP.md` keeps its per-phase entry, deliberately, for the third time: the atomic version-claim guard parses it from `origin/main`, and that is the one remaining per-phase append. Two implementation catches: the `tasks/**` gitignore trap fired for the FOURTH time (v1.18, v1.21, v1.23, now — caught by the probe-first procedure the third occurrence wrote into the Consumer Audit rule), and the spec's "keep the taxonomy note verbatim" caught an attempted reconstruction from a truncated read that had invented mapping values — restored from `git show HEAD:planning.md` instead. 12-assertion `tests/shipped-dir/` suite.
