# v1.20 Concurrent Session Awareness

v1.20 Concurrent Session Awareness, **closes v1.20** (2026-08-28, `tasks/concurrent-session-awareness-spec.md`): `cc --new` (v1.19) made running two, three or four sessions on one project routine, and nothing in `commands/` knew it. The first `/dev` run to hit the new situation found a second live session in kermit-v3, improvised a warning out of raw `ps` output, and got the important part wrong — it told the user not to run `./scripts/gate_fast.sh` while the other session was building, when kermit-v3 wires the take-turns lock at `scripts/gate_fast.sh:163` and a second gate simply blocks on `flock` and waits. That turned a solved problem back into a scary one. Diagnosis found no wrong instruction to correct: `commands/dev.md` had no concurrent-session step at all, and `gate-lock.sh` was documented only in `docs/CONCURRENT-DEV.md`, `shell/worktree/README.md`, and the projects' own gate scripts — so the model improvised, and would improvise differently every run. Fix is a detector, not prose: prose in a command file is advice a model may follow, while a script that prints the same lines every time is a fact. `scripts/check-concurrent-sessions.sh` reports live sessions per worktree, whether worktree mode isolates them, that the running app and its database stay shared regardless, and whether a concurrent `/gate fast` takes turns; `/dev` runs it and reports it verbatim, with two new rules forbidding the improvisation. Same shape as this repo's two prior detectors — standalone, always exits 0, deliberately not wired into `gate_fast.sh`. Three regression guards for findings that each looked plausible and were wrong: kermit-v3 sources the lock but never calls `with_gate_lock`, so the obvious grep reports it unlocked; the main checkout is a string prefix of every worktree under it, so first-match-wins labels worktree sessions `main`; and a missing `/proc` must report `unknown` rather than a count, because telling someone they are alone when they are not is the dangerous failure. One spec deviation, found by running the script before writing its fixtures: path-prefix membership reported all four machine-wide sessions as dev-platform's, since every project lives under dev-platform's own repo root — membership is now `git rev-parse --git-common-dir`, which separates nested repos and unifies a repo with its worktrees. Self-review added a hop bound to the PPid walk. 20-assertion offline suite (mocked `/proc` + real `git init` fixtures), gate at 293 PASS.
