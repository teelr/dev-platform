# v1.28 Consumer Migration Formats — the tools said they served consumers, and served none

v1.28 Consumer Migration Formats, **closes v1.28** (2026-09-03, `tasks/consumer-migration-formats-spec.md`): `migrate-lessons.sh` and `migrate-shipped.sh` each say in their own headers that they are committed rather than run-and-discarded **"so consumer projects can port their own."** That claim shipped in v1.23 and v1.24 and went two Roadmap Phases without anyone running either script against a consumer file. Both failed on every consumer.

## Before

| Consumer | `tasks/lessons.md` | `planning.md` |
| -------- | ------------------ | ------------- |
| kermit | migrated | `FAILS (aborting, 15)` — section is a table |
| kermit-pa | `FAILS (0 of 132 headings parsed)` | no section |
| keystone | `FAILS (0 of 316 headings parsed)` | none |
| OPIE | `FAILS (0 of 5 headings parsed)` | no section |
| SQRL | `FAILS (aborting, 60 rows)` | none |
| kermit-v3 | `FAILS (aborting, 5 rows)` | no section |
| keystone_prototype | `FAILS (0 of 6 headings parsed)` | no section |

**11 of 12 source files failed.** 694 lessons across six consumers, parsed: zero.

The cause: dev-platform's own `lessons.md` was a **table** and its `planning.md` had a `## Recently shipped` **bullet list**, so both parsers encoded dev-platform's format as if it were the format. Every consumer uses heading-per-entry instead. Derivation Sweep in a new costume — not two scripts deriving one value differently, but two scripts each hardcoding the one input shape their author had.

## After

Every consumer parses, `check-migration-coverage.sh` exits 0: kermit-pa 132, keystone 316, OPIE 5, kermit-v3 205 lessons and 139 shipped sections, keystone_prototype 6, kermit 14 shipped rows, SQRL 30 with `--ignore-heading`.

## The detector, written first, rewrote the spec

Change 9 was deliberately ordered ahead of every parser. Its first run falsified the spec that had written it: the survey said `migrate-shipped.sh` "works" for kermit because kermit *has* a `## Recently shipped` section. Nobody had run it. kermit's section holds a `| Version | Date | Summary |` **table**, so the tool fits **zero** consumers, not one — a whole parser's worth of scope, discovered before any code was written against the wrong assumption.

It also caught two of its own bugs. It printed `FAILS` rows and **exited 0**, because `FAILURES` incremented inside a `probe()` running in a command-substitution subshell, where the increment is discarded. And it reported `PARSES (0 entries)` for four consumers whose files were full of lessons, because a parser matching nothing exits cleanly — `rc == 0` is not "worked", and a non-empty source yielding zero entries is a failure.

## What shipped

**`scripts/lib/entry_split.py`** — the format-independent half, extracted once: `slugify`, `titleize`, collision-safe filenames, abort reporting, dry-run/apply emit, and the `Entry` contract between parser and emitter. Near-duplicate across both scripts, and the *near* mattered: `slugify`'s empty-slug fallback was `'lesson'` in one and `'entry'` in the other, so it is a parameter; shipped phases title as `v<X.Y> <Title>` but slug on `<Title>` alone, so `Entry` carries `slug_source` separately; and the two "wrote N files" lines differ, so the apply parenthetical is optional. Collapsing any of the three would have silently renamed files. Changes 2 and 3 were proven byte-for-byte identical on the apply, dry-run and abort paths before any format work began.

**Four new parsers.** Lessons: `## L<N> — title` (688 of the 694 entries; em/en dash and hyphen all accepted) and `## Title (YYYY-MM-DD)`. Shipped: `## Ground Truth (<date>, v<X.Y> <Title> — <status>)` sections, and kermit's `| Version | Date | Summary |` table.

**`--date-from git|today|<date>`** — the numbered format carries no per-entry date, and the tool refuses to invent one. `git` dates each entry from the commit that introduced it, warning by name on any it cannot find. Refused outright on a format that already has dates.

**`--ignore-heading <regex>`, repeatable** — SQRL groups its 30 lessons under 8 category headings at the same `##` level. A naive split invents 8 lessons that do not exist. Unmatched `## ` lines abort and are named; ignored ones are listed in the output, so nothing is dropped silently.

**Detection that does not guess.** Not a raw count: SQRL's file holds a 60-row "Retired Index" table that outnumbers its 30 lesson headings and made a first version pick `table` and abort on all 60 rows. Heading formats now win whenever they appear, because a table inside a lesson body is content while a heading inside a table file is not an entry. Two heading shapes in quantity is genuine ambiguity and aborts. `--format` forces the choice, and the detected format is always printed.

**Duplicates surfaced, not treated as errors.** Lessons: 6 duplicate `L<N>` in kermit-v3, **41 in keystone**, 2 in kermit-pa — real corruption from concurrent appends, reported and migrated as distinct files since the number is not the filename key. Shipped: repeated versions are *normal* (kermit-v3 ships one section per Spec Phase, seven for v0.175), so the report says so rather than letting the collision count read as damage.

16-assertion offline `tests/migration-formats/` covering all five shapes, including the body-table, the duplicate number, the category-heading abort and its escape, ambiguity, and a mechanical verbatim-preservation check. Gate at 403 PASS (+16). Existing `tests/lessons-dir/` and `tests/shipped-dir/` unchanged and green.

**One deliberate behaviour change** beyond the pure refactor: the table path now prints one extra `format: table (N entries)` line, per Change 8's "always print the detected format". Everything else, including every written file, is byte-identical to pre-v1.28.

## Not done here

The consumers are not migrated — the Scope rule forbids writing under `projects/`, and each project's own session runs these. kermit-v3#744 and #745 track the two with open issues. kermit-pa, keystone, OPIE, SQRL and keystone_prototype have no issue filed yet.
