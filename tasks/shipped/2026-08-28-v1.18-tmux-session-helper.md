# v1.18 Tmux Session Helper

v1.18 Tmux Session Helper, **closes v1.18** (2026-08-28, `tasks/tmux-session-helper-spec.md`): Claude Code sessions on this box died several times a day. The cause was not the machine — uptime was 18 days — but the VS Code remote server, which runs with `--enable-remote-auto-shutdown` and a 5-minute timer, and whose exit destroys the pty host and hangs up every terminal, killing every `claude` inside one. A sleeping laptop, a closed window, or a VS Code update was enough. `shell/profile.d/claude-tmux.sh` ships `cc`: attach to (or start) a tmux session named for the project, so the work lives in a tmux server owned by init, outside the VS Code process tree, and a reconnect reattaches instead of starting over. It is a function rather than an alias for three reasons that were each verified before shipping: a running tmux server does not inherit the calling shell's `PATH` (so `claude` is resolved to an absolute path first), quitting claude would otherwise destroy the session (so the pane falls back to `exec "$SHELL" -l`), and tmux treats `.` and `:` as target-syntax separators (so they are stripped, letting worktree directories like `v0.37+phase-1` work). The change also closes a deployment gap that had been documented but never built: `scripts/install.sh` had no `shell` category at all, which is why `shell/new-session.sh` (shipped v1.7) was unreachable except by full path, and why `shell/README.md`'s claim that install "symlinks shell helpers into `~/.shell-platform/`" described code that did not exist. `install_shell` deploys `shell/profile.d/*.sh` to `~/.claude/profile.d/` and prints the `.bashrc` loop to add, the same way `install_git_hooks` prints its `git config core.hooksPath` line rather than editing anything. The target is deliberately depth 2: `uninstall.sh` sweeps `find ~/.claude -maxdepth 2 -type l`, so the nested `~/.claude/shell/profile.d/` the draft proposed would have survived uninstall with `.bashrc` still sourcing this repo. `scripts/verify.sh` gains the matching drift check, and `scripts/gate_fast.sh` adds `shell/` to its bash-syntax scan roots — which had never covered `new-session.sh` or `shell/worktree/`, the gap `tests/worktree/run.sh` had been hand-patching with its own `bash -n` calls. New 18-assertion `tests/shell/` suite: argument handling under `set -u`, session creation and name sanitisation, cwd, argument pass-through, reattach-not-duplicate, `-n`, `--kill`, survival after claude exits, and an install/uninstall round-trip whose uninstall assertion is what makes the depth-2 path choice load-bearing rather than cosmetic. It runs against its own tmux server via `TMUX_TMPDIR` with a stub `claude`, so it never touches live sessions — one of which is usually the Claude Code session running the gate. Three defects were found in the drafted material and fixed rather than shipped: the new file was silently gitignored (`.gitignore`'s `shell/**`; `!shell/*.sh` does not reach subdirectories, same reason `git-hooks/` and `worktree/` each needed their own rule), the deploy path was one level too deep for uninstall, and `cc --kill`/`cc -n` with no argument referenced `$2` unguarded, aborting the shell under `set -u` instead of printing the usage error. Two errors in the spec itself surfaced during `/code` and were corrected in the spec file: its Change 1 acceptance test used `git check-ignore -v` expecting exit 1, but `-v` reports negation matches and exits 0 either way (so the test would have passed whether or not the fix worked — `-q` or `git add -n` is the real check); and the deploy had to move out of post-merge into Change 3, because `verify.sh`'s new check runs inside `gate_fast`'s always-on lift checks and `/gate fast` must pass before commit while post-merge runs after it. `cc` shadows `/usr/bin/cc` by deliberate choice — build tools invoke `cc` through `execvp` and bash functions are not inherited by child processes, so `make`/`cargo`/`cmake` are unaffected; only typing `cc foo.c` at a prompt changes, and `command cc` still reaches the compiler. Documented in `shell/README.md` and in `cc --help`. Not included: the `~/.bashrc` edit (the profile.d loop, plus removing a dead `~/dev/tools` PATH entry, 15 aliases pointing into that missing directory, and a source of a non-existent `~/dev/ai_dev/.bash_aliases` — all re-verified absent on disk) is a post-merge step requiring the user's confirmation, since it changes shell startup outside the repo. The tmux save/restore-layout workflow those dead aliases represented is not rebuilt here; that would be its own Roadmap Phase, built in-repo so it cannot be lost the way the untracked `~/dev/tools` was.
