# v1.15 Post-Merge Change Summary

v1.15 Post-Merge Change Summary, **closes v1.15** (2026-08-20, `tasks/post-merge-change-summary-spec.md`): the standard post-merge Roadmap-Phase-completion sub-step (v1.10) only fires when a merge closes the last Change of a phase, so most merges — mid-phase Changes, standalone chores/fixes — shipped with zero post-merge summary. Adds a second standard (non-bespoke) post-merge sub-step, unconditional on phase completion: every `/merge` invocation ends its report with a short Problem/Opportunity → What shipped summary, chat-report only (no new file, no CHANGELOG, no GitHub Release/PR comment — the user's explicit pick among four scoped options). Derives the summary from context already available at merge time via a 3-tier fallback rather than regenerating from scratch: (1) the lines the merge added to `planning.md`'s "Recently shipped" section — the exact prose `/code` already wrote pre-commit and `/review` already approved; (2) the merged spec's Problem/Design-Philosophy framing + Change titles if `planning.md` wasn't touched; (3) the PR title/body via `gh pr view` if no spec was touched at all — the spec-less-chore case that previously got no post-merge output whatsoever. `commands/merge.md` Step 7 restructured so the summary now generates BEFORE the existing "no spec touched → stop" early exit, which previously skipped it for exactly that case; sub-steps renumbered 1-7. Lockstep documentation across `CLAUDE.md`, `settings/claude-global.md`, `skills/WORKFLOW_MANUAL.md` — same shape as v1.10's Roadmap-Phase-completion rollout. Deliberately ships with no new script or test suite: this is an instruction-file change with no runtime behavior to unit test, same class as v1.7 Plan-Time Isolation. Does not touch the workflow chain string itself or `audit-project-drift.sh`'s chain-detection regex — confirmed `audit-project-drift.sh --project dev-platform` still reports CLEAN. Gate unaffected (no code/test changes; `check_spec_taxonomy.sh` clean). Released, milestone #26 closed.
