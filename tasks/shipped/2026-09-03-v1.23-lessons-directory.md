# v1.23 Lessons Directory

v1.23 Lessons Directory, **closes v1.23** (2026-09-03, `tasks/lessons-directory-spec.md`): `tasks/lessons.md` was one append-only table that every `/code` turn added a row to. With a single session that is fine. With three or four it is a standing merge conflict — every session appends at the same place, so git either conflicts outright or, worse, merges cleanly at different line offsets and leaves a silent duplicate. v1.21's own `git stash pop` hit the first variant, and v1.11 had already deferred this as "the doc-merge-collision redesign". The fix is structural rather than procedural: one file per lesson, `tasks/lessons/<date>-<slug>.md`. Two sessions cannot touch the same file, so the conflict class stops existing instead of being detected — v1.17 shipped a detector for the numbering half of this problem; this removes the cause. Scope was deliberately one file of the three: `ROADMAP.md` is read by six scripts and four commands, including the atomic version-claim guard which parses it out of `git show origin/main:ROADMAP.md`, so splitting it would put the most load-bearing mechanism in the repo at risk to fix its least frequent conflict. `tasks/lessons.md` had the highest append rate and the lightest coupling — nothing here machine-reads it. The migration script is committed rather than discarded so consumers can port their own `L#`-numbered lessons, which collide on the number as well as the line. Its hard part is parsing: 7 of the 46 rows carry literal pipes inside backticks, so splitting on `|` mangles them — it anchors both ends with a greedy middle field, aborts on any unparseable row rather than skipping it silently, and always writes the full original text to the body so a bad title split cannot lose content. Preservation was verified mechanically after the run rather than eyeballed: 46/46 bodies verbatim exactly once, 7/7 pipe-bearing bodies intact. Two traps, one caught by the plan and one only at `/code` time. `.gitignore`'s `tasks/**` with `!tasks/*.md` does not reach subdirectories, so all 46 files would have been silently untracked — the third occurrence after v1.18 and v1.21, which is why that fix runs first. And the spec listed the scaffolding *tree comments* but missed `scaffolding/*/tasks/lessons.md`, three real stub files, so every newly scaffolded project would have been born with the old colliding format — grepping for references found the documentation; only globbing for the filename found the artifacts. Also retires the "~30 entries" cap as a storage limit (it existed to keep one file readable, and was already violated at 46) and drops `git check-ignore -v` from the Consumer Audit rule, since it exits 0 on a negation match and so cannot distinguish ignored from re-included. 9 assertions, gate at 329 PASS.
