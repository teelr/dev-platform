# v1.21 Host Agnostic Repo Detection

v1.21 Host Agnostic Repo Detection, **closes v1.21** (2026-08-28, `tasks/host-agnostic-repo-detection-spec.md`, closes [issue #77](https://github.com/teelr/dev-platform/issues/77)): SQRL could not run `/plan` at all. Its remote is `git@github-teelr129:Osigin-LLC/SQRL.git` — the SSH host-alias multi-account shape dev-platform's own docs prescribe for that separate account — and `claim_roadmap_version.py` derived `owner/repo` with a regex anchored on the literal host `github.com`, so it raised and `/plan` Step 2 hard-stopped. The project had been running on `VERSION_GUARD_REPO_SLUG`, a test-only override, in production. Two other scripts shared the assumption and failed differently: `check_version_collision.py` returned `None` and degraded to SKIP/exit 2 — honest, and the v1.12 lesson already encoded, but SQRL's CI silently lost its milestone cross-check; and `check-phase-milestones.sh` left the URL intact, whereupon its shape guard passed it (the URL contains exactly one slash), the raw remote reached `gh api`, and the resulting 404 was reported as `(gh auth/network?)` — a parsing bug wearing an auth error's clothes. A sweep of every remote found two affected projects, not one: `gosqrlgo-dispatch` is on the same alias and would have hit this the moment it planned. The fix is one parse, `scripts/lib/repo_slug.py`, imported by both Python callers and called as a CLI by the shell one — chosen over three regex edits because this is the THIRD Roadmap Phase spent on one derivation rule duplicated across scripts (v1.12's roadmap regex in two, v1.13's `ROADMAP_PATH` in three with one never named in the issue), and every one was found by a consumer rather than by the change that had just edited a sibling. That recurrence is now a `CLAUDE.md` Derivation Sweep rule. Two things the spec did not predict, both caught by verifying rather than assuming: the new `.py` file was silently gitignored because `.gitignore` allowed only `!scripts/lib/*.sh` (the v1.18 defect, and the one consumer-audit item the spec had flagged as able to bite); and widening the parse broke an existing test whose fixture origin was a local path chosen precisely because the old regex rejected it — the replacement had to be an origin git can still fetch from but that cannot yield owner/repo, which is a relative path. Also fixed a second latent bug free: dotted repo names never parsed either. 14-assertion `tests/repo-slug/` suite plus alias regressions in both existing suites, one proving via captured mock-`gh` argv that the query reaches GitHub as `repos/Osigin-LLC/SQRL/`. Gate at 310 PASS (+17).
