# v1.50 Link Deps Existing Destination

v1.50 Link Deps Existing Destination (2026-11-03, `tasks/link-deps-existing-destination-spec.md`):
fixes issue #156, the "found, not fixed" item from v1.49.

## The problem

`shell/worktree/link-deps.sh` ran `ln -sfn "${src}" "${dst}"` without looking at what already
existed at `dst`. Probed on 2026-11-03 against scratch fixtures:

| Destination already in the worktree | Result |
| ----------------------------------- | ------ |
| Real directory, empty or not | link created INSIDE it, `linked` printed, exit 0, nothing linked at the destination |
| Real regular file (a worktree-local `.env`) | silently replaced by the symlink, content lost, `linked` printed |
| Symlink to a directory (a second run) | replaced in place, idempotent |
| Broken symlink | replaced |

The directory case is the same false `linked` as issue #154 by a path v1.49's `ln` result check
cannot see, because `ln` succeeds. The file case was silent data loss.

## What shipped

- `link-deps.sh` refuses a destination that exists and is not a symlink:
  `WARN could not link: <entry> (destination exists and is not a symlink)` on stderr, counted in
  the v1.49 `failed` counter, the remaining entries still tried, exit 1 with
  `N linked, M missing, K failed`. Nothing is deleted or linked into. A symlink at the
  destination, valid or broken, is still replaced, so running the script twice is safe.
  Decisions for both the directory and the file case came from the user at pick-up.
- `shell/worktree/README.md` describes the refusal and says how to resolve it (move or delete the
  real file or directory, run again). Usage text and header comment updated.

- New checks in `tests/worktree/run.sh` (4a-5 to 4a-8): real directories (one with a file, one
  empty) refused and untouched while the next entry still links; a real file refused with its
  content kept; a second run idempotent with no nested link; a broken symlink replaced.
- Mutation proof, run against the real file edited in place, one mutation per call, restored from
  a saved copy and diffed identical afterwards: deleting the new check failed the real-directory
  and real-file cases; testing for directories only failed the real-file case alone; refusing

  `.claude/worktree-deps` of kermit, kermit-pa, kermit-v3, keystone and SQRL): all 16 entries have

  `/home/rich/dev/shell/worktree/link-deps.sh`, so the change is live at merge.

## Deviation from the spec

An existing test failed once the check was in: the `tests/worktree/run.sh` fixture for the
no-argument form (cases 4b-4d) committed its `.env` into the throwaway repo, so the fresh worktree
already held a real `.env` and the script now refused to link over it. Real projects git-ignore
`.env`, so the fixture now writes a `.gitignore` containing `.env` before committing. The spec did
not list this fixture.

## Scope honesty

- The check fires only when something created a real file or directory at a listed path before
  `link-deps.sh` ran (for example a dev server started in the worktree first, which creates
  `frontend/.next`). Whether that has happened in practice is unverified.
- Any project that relied on the script overwriting a real file now gets exit 1 on that entry. No
  consumer was run against the new script.
- A destination whose parent path contains a symlink is not examined; only the destination itself
  is tested.
