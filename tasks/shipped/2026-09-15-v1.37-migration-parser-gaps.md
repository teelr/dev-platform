# v1.37 Migration Parser Gaps — a self-correction of v1.36's own record

v1.37 Migration Parser Gaps (2026-09-15, `tasks/migration-parser-gaps-spec.md`): `v1.36`'s shipped
record and both its PR bodies wrote "kermit's `lessons.md`/`planning.md` fail to parse" and filed it
as out of scope for dev-platform, a `teelr/kermit-harness` problem. **That characterization was
investigated, found wrong, and corrected before any issue was filed** — the user asked for a
kermit-harness issue to be filed for these findings; instead of complying, this session read the
actual files first and found both "failures" were dev-platform's own detector misclassifying an
already-fully-migrated file.

## What was actually wrong

- **`tasks/lessons.md`**: all 152 real lessons are already split into `tasks/lessons/` (175 files
  exist there now). What's left is a permanent lookup table (`## Renumbering note — 2026-08-31`,
  resolving old L-numbers for archived spec citations) — explicitly documented in the file itself as
  intentionally kept. `migrate-lessons.sh`'s `detect()` found zero `## L<N>` headings and fell back to
  counting any `| `-prefixed line in the whole file as "table format," which the renumbering table's
  rows satisfied, so it misdetected `table` and aborted trying to parse them as
  `| Date | Lesson | Project | Status |` rows.
- **`planning.md`**: its `## Recently shipped` section held a real table until 2026-09-07, when
  `migrate-shipped.sh` extracted all 14 entries into `tasks/shipped/` (30 files exist there now).
  What's left under that heading is 8 lines of explanatory prose. `detect()` found no table rows and
  fell back to `'bullets'`, whose parser allows exactly one non-bullet "preamble" line before
  aborting.
- **The "157 entries in a different bullet format" story in `planning.md`'s own prose is real, but
  is NOT what was failing** — that's `teelr/kermit-harness#396` (closed), a genuinely separate,
  already-tracked, still-open decision about a *different* heading (`## Where work stands`) the tool
  has never read. Not touched here.

## What shipped

- **`scripts/migrate-lessons.sh`**: `detect()` now only counts a `| ` line toward "table format" if
  it matches the table's actual 4-column shape (`ROW`) with a real date in the first column — not
  merely "starts with a pipe." When nothing matches any known format but a `## ` heading exists, it
  reports `"nothing to migrate"` (the same phrase the missing-file case already uses) instead of
  misdetecting and aborting.
- **`scripts/migrate-shipped.sh`**: `detect()` now requires at least one line matching `PHASE` or
  `BULLET` before choosing `'bullets'`; otherwise it reports `"nothing to migrate"` instead of forcing
  the bullets parser onto prose.
- **`check-migration-coverage.sh` needed no changes** — verified by reading its `probe()` source: it
  already treats the `"nothing to migrate"` phrase as `MIGRATED` (when the target directory has
  files) or `NO SECTION`, so the fix is entirely localized to the two `detect()` functions.
- **`tests/migration-formats/run.sh`**: 2 new fixtures (one per script) reproducing kermit's exact
  shape.
- **`tests/migration-coverage/run.sh`**: 1 new end-to-end fixture (`residual-1`) proving
  `check-migration-coverage.sh` reports `MIGRATED`, not `FAILS`, for this shape.
- **`ROADMAP.md`**: `v1.36`'s entry gets a `**Corrected in v1.37:**` note, matching the existing
  `v1.26`-entry precedent — the original text is not rewritten.

## A real regression the adversarial self-review pass caught and fixed before this shipped

The first version of the `migrate-lessons.sh` fix used a **position-based** heuristic: only count
`| ` rows found *before* the first `## ` heading, reasoned from the assumption that "a genuine
table-format file is a flat table under one H1, never mixed with `## ` subsections." Running the
*existing* test suite (not just the new fixtures) immediately broke 6 previously-passing checks in
`tests/lessons-dir/run.sh` — its `good.md` fixture, dev-platform's own canonical table format, has a
real `## Active Lessons` heading directly *before* its table, exactly the shape the assumption said
couldn't exist. **Fixed by replacing the position check with a schema check**: a row only counts if
it matches the table's actual 4-column-plus-date shape (`ROW.match(l) and DATE.match(m['date'])`),
a property of the row's content, not its position relative to other structure. Verified this also
preserves the existing "a malformed table row aborts" behavior (`tests/lessons-dir/run.sh`'s
"a malformed row aborts and writes nothing" check still passes) — the schema filter only changes
which FORMAT gets chosen, not what `parse_table()` does once a format is chosen. Lesson:
`tasks/lessons/2026-09-15-position-based-heuristics-need-a-counterexample-not-just-a-motivating-example.md`.

**Deviation from the spec's literal code**: the spec (written during `/plan`) specified the
position-based version verbatim, having verified it only against kermit's real file — not against
this repo's own existing fixtures. The shipped code differs from the spec's Implementation section;
the spec file itself is left as-written (the historical plan), per the same precedent `v1.35`/`v1.36`
followed for their own mid-implementation fixes.
