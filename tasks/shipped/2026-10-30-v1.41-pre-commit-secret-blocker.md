# v1.41 Pre-Commit Secret Blocker

v1.41 Pre-Commit Secret Blocker (2026-10-30, `tasks/pre-commit-secret-blocker-spec.md`):
a scan of the local projects found real-looking credentials committed to private repos (an
OpenAI key in `kermit-harness`, a Google Maps key in `SQRL`, plus tracked `.env` files) with
nothing to stop them. Secret scanning is off on the private repos, so this adds the check at
the earliest point, before the commit exists.

## The verified problem

- `~/.claude/git-hooks/pre-commit` is deployed, but no local project uses it (checked by a
  script reading `core.hooksPath` across `projects/*`). `kermit`, `keystone` and `SQRL` set
  `core.hooksPath` to their own `.git/hooks`; `kermit` and `kermit-pa` each have a `pre-push`
  hook there that `core.hooksPath ~/.claude/git-hooks` would have silently disabled.
- The old hook did nothing without `scripts/gate_fast.sh`, which 9 of the 18 local projects
  have (`bash scripts/check-secret-hook.sh`, GATE column).
- `settings/settings.json` denied only `git commit --no-verify*`, so by the docs' whole-command
  matching `git commit -m x --no-verify` and `git commit -n` were not covered. That was a gap
  in v1.39's own deny list.

## What shipped

- `shell/git-hooks/pre-commit`: a secret scan that runs first, in every repo. It looks only at
  added lines and names the pattern, file and line, never the matched text. Content patterns:
  GitHub, Anthropic, OpenAI, AWS, Google, Slack and HuggingFace token shapes and private-key
  blocks; path patterns: `.env` / `.env.*` (not `.example`, `.sample`, `.template`, `.dist`)
  and key files. Bypass `SKIP_SECRET_SCAN=1`; allow a path via `.secret-scan-allow` or a line
  via `secret-scan:allow`. `SKIP_GATE_FAST=1` does not skip it. A new
  `git config devplatform.precommitGate false` turns the gate part off per repo.
- `scripts/check-secret-hook.sh`: read-only report of which projects have the hook
  (`ENABLED`, `NOT-ENABLED`, `OTHER-HOOK`). On this machine it reports 0 of 18 enabled.
- Four new deny rules for `--no-verify` and `-n` on `git commit` and `git push`.
- `tests/git-hooks/run.sh` grew from 5 to 31 PASS (0 FAIL); fake credentials are built at
  runtime so no key-shaped string is committed.

## Findings

- A `grep -q` fast path in the first draft skipped the scan on any large commit: `-q` exits at
  the first match, the upstream `grep` dies of SIGPIPE, and under `pipefail` that read as
  "no match". A secret in a 10,001-line commit passed. Found by a sanity script, not by the
  original tests (their diffs were tiny); fixed with `grep -c` and covered by a regression
  test that checks the right line number. See
  `tasks/lessons/2026-10-30-grep-q-under-pipefail-skips-large-inputs.md`.
- Self-review of the diff found two more gaps, both fixed and covered by a test: a secret added
  while renaming a file was missed (`--diff-filter=AM` excludes renames; now `ACMR`), and a file
  name git quotes (a double quote in it) was silently skipped.
- Enabling uses a one-line symlink at `.git/hooks/pre-commit`, not `core.hooksPath`, so a
  repo's other hooks keep running.
- Enabling the hook in a repo that has `scripts/gate_fast.sh` also runs the gate on every
  commit; the new config switch exists for that.

## Not covered

- Not enabled anywhere yet. Enabling is a one-line action the user runs in each project;
  dev-platform sessions do not write into `projects/`.
- Only provider-shaped tokens and `.env` / key files; no generic-password or entropy rule, no
  history scan, and `git commit --no-verify` run directly in a terminal still skips it.
- Whether a deny pattern matches a given command is verified by the docs' wording only, not
  by an offline test.
- The new deny rules take effect after `./scripts/install.sh settings`.
