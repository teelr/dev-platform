# v1.34 Cross-Session Collision Guardrails — visibility and a hardened flag for concurrent sessions

v1.34 Cross-Session Collision Guardrails, closes v1.34 (2026-09-14, `tasks/cross-session-collision-guardrails-spec.md`, [issue #120](https://github.com/teelr/dev-platform/issues/120)): a kermit-v3 dependency ask filed under the cross-repo comms protocol. `cc --new` makes 3-4 concurrent sessions on one project routine, and two failure modes went unguarded — sessions sharing the literal same checkout directory unisolated, and a session proposing work another session is already doing. The issue proposed three directions to spec out and was explicit that none was a commitment, the same framing issue #118 used for v1.33.

## What shipped

**Each of the three proposed directions was checked against what's actually buildable before being scoped in or out — this is where the spec earned its keep.**

**Peer-visibility preflight (shipped as proposed).** `/plan` now calls `ListAgents` before claiming a Roadmap Phase version (`commands/plan.md` Step 2), surfaces any peer session whose name or location looks related to the feature about to be planned, and asks the user to confirm before proceeding. Advisory only — `ListAgents` carries no project or task metadata, so a "looks related" match is a prompt to ask, never a fact to act on or block on. Added `ListAgents` to `/plan`'s `allowed-tools`.

**Session self-naming (verified NOT buildable as the issue described — scoped down).** The issue assumed `/plan` (or "session start") could set a session's own `ListAgents` display name. Live evidence backed the *problem*: `ListAgents` was called mid-planning and this very session showed as the generic `dev-93`, next to peers like `kermit-v3-47`, `kermit-95` (same generic `<dir>-<suffix>` shape) beside others with real descriptive titles (`"Canvas tab naming convention"`, `"MP3 transcription audit"`). A `claude-code-guide` research pass was then dispatched to confirm the *mechanism* rather than assume one, because a spec built on an assumed capability is exactly the failure mode `/plan`'s own instructions warn against. Its sourced answer (`code.claude.com/docs/en/sessions.md`): accepting a plan in Claude Code's own built-in plan mode auto-titles a session, and a human can run `/rename <name>` — but no CLI flag, config, or tool call lets an agent set its own session's display name, and `/plan` doesn't invoke the harness's plan-mode tools (`EnterPlanMode`/`ExitPlanMode`). Scoped down to what's real: `/plan` now suggests the human run `/rename <title>` after creating the branch/worktree.

**Worktree adoption guard (shipped, narrowly scoped).** New `hooks/worktree-guard.sh`, wired as a second `SessionStart` entry in `settings/settings.json` alongside the existing telemetry hook. `scripts/check-concurrent-sessions.sh` already detected "worktree mode ON, session in the shared main checkout" — but only when a human remembered to run `/dev`. The new hook fires automatically, for every session, and is silent unless the actual collision shape is present: worktree mode ON (`.claude/worktree-deps` marker), the session is NOT already inside `.claude/worktrees/`, and the current branch is not `main`/`master`. Deliberately narrow — `CLAUDE.md`'s Trivial-Edit/Quick-fix carve-out legitimately commits straight to `main` in the shared checkout with no branch at all, and must never warn; a `SessionStart`-only, fire-once check avoids turning this into per-`Edit`/`Write` noise, and the hook never prints `check-concurrent-sessions.sh`'s full report on every start (that would spam every session across the fleet for the common, correctly-isolated case). Known, stated limitation: only catches the state a session *starts* in — a mid-session `git checkout -b` bypassing `/plan`'s worktree flow isn't re-checked, since `SessionStart` fires exactly once.

## Scope decisions

- **No shared task-claim registry, lock file, or "claimed work" ledger** — explicitly out of scope per the issue's own Non-goals.
- **No file under `projects/` touched** — every Change lands in dev-platform's own `commands/`, `hooks/`, `settings/`, `tests/`.
- **No attempt to fake agent-side session renaming** (e.g. writing a name to a file and hoping the harness reads it) once the research pass confirmed no such mechanism exists.
- **README.md's gate-check count corrected** from a stale `448 checks` (accurate as of v1.32, never updated through v1.33's 463) to the verified `470 checks, ~47s` — caught in passing while touching the doc-sync step for this phase, not a change the spec asked for on its own.
