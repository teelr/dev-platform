# v1.19 Parallel Coding Sessions

v1.19 Parallel Coding Sessions, **closes v1.19** (2026-08-28, `tasks/parallel-coding-sessions-spec.md`): running more than one Claude Code session on the same project was harder than it should be — `cc` names its tmux session after the directory and attaches to an existing one, so a second `cc kermit-v3` just reattaches to the first, and the escape hatch (`cc -n review kermit-v3`) made you invent a name and remember it to get back. `cc --new` starts the next free numbered session in the same directory (`kermit-v3-2`, then `-3`, then `-4`) and `cc -n kermit-v3-2` returns to one. It picks the lowest free suffix rather than counting, so killing `-2` frees that name again, and it refuses `--new` together with `-n` rather than silently letting one win. The notable decision is what `--new` does NOT do: no git, no branch, no worktree. Scoping it started as "a worktree per session" and changed at plan time after one sweep of `projects/*/.claude/worktree-deps` — the five projects real coding happens in (kermit, kermit-pa, kermit-v3, keystone, SQRL) have all already opted into worktree mode, so `/plan` Step 2 already gives each session its own copy of the repo via `EnterWorktree` and `/merge` Step 5 already tears it down. Two `cc --new` sessions sitting in the main checkout on `main` collide over nothing until `/plan` runs. `cc` also could not do it correctly: a fresh worktree needs the project's heavy git-ignored paths symlinked in from the main checkout, and that list is per-project in a committed manifest, which is exactly why worktree mode is opt-in. For the thirteen branch-mode projects `--new` prints one warning line that the session shares a working tree and a branch, and points at the opt-in. Retires `shell/new-session.sh` (v1.7): `cc --new` covers "another session here", `/plan` covers branch creation, and it was never deployed by `install.sh` so there were no users to migrate. +10 assertions in `tests/shell/run.sh`, gate at 273 PASS. One spec correction at `/code` time: the spec quoted the gate baseline as 262 from v1.18's ROADMAP entry, but PR #79 had since added an assertion, so the real baseline was 263. Deferred deliberately: opting dev-platform itself into worktree mode, since `install.sh` symlinks `~/.claude/*` at repo paths and installing from a worktree would leave the live deployment pointing into a directory `/merge` later deletes.
