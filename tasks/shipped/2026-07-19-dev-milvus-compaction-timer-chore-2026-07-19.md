# Dev Milvus compaction timer chore (2026-07-19): found live during a kermit-v3 session…

Dev Milvus compaction timer chore (2026-07-19): found live during a kermit-v3 session investigating flaky Playwright tests — four separate dev/test Milvus containers (kermit-dev, keystone-dev, kermit-test, kermit-pa) were stuck in a perpetual ~10s "force trigger a level zero compaction" retry cycle, each pegging a full CPU core continuously, from an accumulated backlog of dropped segments (one collection had 119 of 122 total segments marked dropped, from months of automated-test churn). A manual `Collection.compact()` call cleared kermit-dev-milvus's backlog completely (CPU 100%+ → 2.46%). Added `scripts/compact_dev_milvus.py` (auto-discovers every running `*milvus*` container via `docker ps`, no per-project hardcoding, resolves each one's published gRPC host port, compacts every collection found) + `deploy/systemd/dev-platform-milvus-compact.{service,timer}` (oneshot + 6-hourly `OnCalendar` timer, `Persistent=true` to catch up after the box's nightly power-off) + `scripts/install-milvus-compact-timer.sh` (mirrors kermit-v3's own `install-systemd.sh` pattern — a dedicated installer since systemd units target `~/.config/systemd/user/`, a different deployment surface than `~/.claude/`, not folded into `scripts/install.sh`'s existing categories). Consumer Audit: `.gitignore`'s allow-list needed a new `deploy/` top-level entry (its blanket `*` default would have silently ignored the new unit files) — added `!deploy/` + `!deploy/**/` + `!deploy/systemd/*.service`/`*.timer`. `scripts/verify.sh`/`install.sh` confirmed out of scope — both are `~/.claude/`-symlink-specific, unrelated to this systemd-copy deployment. `./scripts/gate_fast.sh` green (212 PASS). Scoped to dev-platform rather than kermit-v3 since the same symptom reproduced across every sibling project's Milvus instance, not just kermit-v3's own.
