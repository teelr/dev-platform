# v1.13 Configurable Roadmap Path

v1.13 Configurable Roadmap Path, **closes v1.13** (2026-08-13, PR #65, `tasks/configurable-roadmap-path-spec.md`): closes [issue #64](https://github.com/teelr/dev-platform/issues/64), filed by Keystone's session — `check_version_collision.py` and `check_spec_taxonomy.sh` both hardcoded `ROADMAP.md` at the repo root, silently no-op'ing for Keystone (roadmap lives at `docs/roadmap.md`, no `planning.md` at all). Keystone's first fix attempt (symlinking root `ROADMAP.md` to the real file) made it worse: `git show origin/main:ROADMAP.md` doesn't dereference symlinks, producing false `COLLISION` failures against their own milestone history (reverted same night). Adds a `ROADMAP_PATH` env var (default `ROADMAP.md`, fully backward-compatible) to all three scripts that read the roadmap — including `claim_roadmap_version.py`, not named in the issue but with the identical bug, fixed alongside the other two. Documents the symlink footgun explicitly. Every new test proves both the override works and default behavior is unchanged. Gate at 228 PASS (+4). `/review` found no issues (swept `scripts/` for other hardcoded `ROADMAP.md` references — `sync-milestones.sh` has its own pre-existing, differently-shaped override; `audit-project-drift.sh` transparently inherits the fix via env-var propagation).
