# Consumer template missing `permissions:` block for cross-org reusable-workflow calls (2026-08-12, PR #63)…

Consumer template missing `permissions:` block for cross-org reusable-workflow calls (2026-08-12, PR #63): found live on SQRL's v1.12 pin-bump adoption (Osigin-LLC/SQRL#139) — their `dev-platform-gate.yml` had no `permissions:` block, so GitHub silently rejected the cross-org reusable-workflow call (Osigin-LLC calling teelr/dev-platform) with a `startup_failure` that never appeared in the PR's checks list; the `version-collision` job (needs `issues: read`) just never ran. Adds a top-level `permissions: {contents: read, issues: read}` block to the consumer template plus a comment explaining why it's required for cross-repo/cross-org calls specifically. Documents the symptom in `docs/CI-INTEGRATION.md`'s troubleshooting table. Re-synced the already-staged (uncommitted) template copies in the 5 other consumer working trees so they wouldn't hit the identical failure. Gate at 224 PASS.
