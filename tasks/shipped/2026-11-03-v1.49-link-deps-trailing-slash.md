# v1.49 Link Deps Trailing Slash

v1.49 Link Deps Trailing Slash (2026-11-03, `tasks/link-deps-trailing-slash-spec.md`):
fixes issue #154, found while building v1.48.

## The problem

`shell/worktree/link-deps.sh` never checked whether `mkdir` or `ln` worked. It printed
`linked <entry>`, counted it and exited 0 either way. Probed on 2026-11-03 against scratch
fixtures:

- `a/node_modules/`, `a/node_modules//` and a bare `node_modules/` all failed with
  `ln: failed to create symbolic link '.../a/node_modules/': No such file or directory`
  (a path ending in `/` cannot be created as a link). Nothing existed in the worktree
  afterwards, yet the output said `1 linked, 0 missing`.
- The same false report came from a failed `mkdir -p` (a read-only worktree directory, or a
  regular file where a directory was needed).
- The entry `/` was accepted and linked inside the worktree directory.

## What shipped

- `link-deps.sh` strips trailing slashes from an entry, rejects an entry that is only
  slashes (`WARN invalid entry (no path)`), and checks `mkdir` and `ln`. A failed entry
  prints `WARN could not link: <entry>`, is counted as failed, and the loop carries on with
  the rest. The summary stays `N linked, M missing` when nothing failed and becomes
  `N linked, M missing, K failed` otherwise; the script then exits 1 (it exited 0 before).
  A missing source is still a warning with exit 0.
- `scripts/check-dep-install-needed.sh` strips trailing slashes the same way, so it names
  the directories that actually link. This reverses the v1.48 decision not to strip, which
  was right while `link-deps.sh` did not link such entries.
- `shell/worktree/README.md` no longer tells people to write entries without a slash.

## Verification

- New checks: four in `tests/worktree/run.sh` (one and two trailing slashes, a root
  `node_modules/`, a failed link that still lets the next entry link and exits 1, a
  slash-only entry). The failed-link case puts a regular file where a directory is needed,
  so it does not depend on file permissions. `tests/dep-install-notice/run.sh` check 9 now
  expects the trailing-slash entry to be recognised; its parity check runs one manifest
  through both scripts.
- Mutation proof, run against the real files edited in place, one mutation per call,

  from `link-deps.sh` failed the trailing-slash, root-slash, slash-only and parity checks;
  removing the `mkdir`/`ln` result check failed the failed-link check; removing the slash
  stripping from the notice script alone failed the messy-manifest and parity checks (this
  is what shows the parity test guards the two copies); exiting 0 after a failure failed the
  failed-link and slash-only checks.
- `ls -l ~/.claude/worktree/link-deps.sh` shows a symlink to
  `/home/rich/dev/shell/worktree/link-deps.sh`, so the fix is live at merge.

## Scope honesty

- The exit status is a contract change: 0 became 1 when a link fails. `/plan`, `/code` and
  `/merge` run the script as a plain command and read its output. Whether kermit-v3 or
  another consumer wraps it and treats a non-zero exit specially was not checked.
- No consumer manifest was scanned for a trailing-slash entry, so how many projects had
  silently unlinked dependencies is unknown.
- Found and not fixed: when the destination already exists as a real directory,
  `ln -sfn` creates the link inside it and the script prints `linked`, though no link exists
  at the destination (probed 2026-11-03). It needs its own decision (replace, warn or
  refuse).
