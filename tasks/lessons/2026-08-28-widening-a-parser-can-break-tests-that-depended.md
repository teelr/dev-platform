# Widening a parser can break tests that depended on it FAILING. v1.21…

Widening a parser can break tests that depended on it FAILING. v1.21 made repo-slug parsing host-agnostic; `tests/version-collision/` had a check whose fixture origin was a local path (`/tmp/vc.XXX/origin.git`) chosen precisely because the old `github.com`-only regex rejected it, giving the degraded-SKIP path under test. The widened parse resolved it to `vc.XXX/origin`, so the run took the gh-api path and the assertion broke. The naive fix (point origin at `garbage`) failed differently — an unfetchable URL dies at `git fetch origin/main` before reaching the slug layer at all. The case that still works is a RELATIVE origin (`../origin.git`): unparseable (no segment before its only slash) but still fetchable. When relaxing a validator, grep the test suite for fixtures that exist to be rejected by it.
