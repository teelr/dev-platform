# Read the command's actual error output BEFORE theorising about why it failed…

Read the command's actual error output BEFORE theorising about why it failed. Chasing an intermittent `gate_fast` hang, I asserted two root causes from timing experiments and got both wrong: first a stdin deadlock (the `sleep 600 | cmd` test was measuring `sleep`, since a pipeline waits for every stage — `timeout 8 bash -c 'sleep 600 | true'` also returns 124), then "intermittent flake" (it was deterministic). Simply running `code --install-extension` and reading stderr gave the answer in one step: `connect ENOENT /run/user/1000/vscode-ipc-*.sock` — the VSCode REMOTE CLI talking to a server that had exited, via a `$VSCODE_IPC_HOOK_CLI` this shell inherited before the reconnect. Two wrong theories and a discarded branch cost more than one `2>&1` would have.
