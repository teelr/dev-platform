# Changing the canonical workflow-chain STRING is a lockstep edit across ~12 files…

Changing the canonical workflow-chain STRING is a lockstep edit across ~12 files, and the new drift-detector substring must not appear bare in any file the detector scans. v1.3 inserted `/review` into the chain; the review-less chain is detected by the exact substring `/code → /gate fast`. dev-platform is in its own registry (path `.`), so `audit-project-drift.sh` greps dev-platform's OWN `CLAUDE.md` — writing a bare review-less chain example there would self-flag the repo as DRIFT (3rd recurrence of the v0.9 "detection must not self-match documentation" hazard). Fix: describe the review-less case in prose only ("omits the mandatory `/review` gate"), never as a literal `…/code → /gate fast…` string, and verify `audit --project dev-platform` reports CLEAN before commit. SECOND trap (caught by `/review`, not self-review): the detector substring MUST match the rewrite target exactly. First cut detected the broad `/code → /gate` but the insert rule only rewrites `/code → /gate fast` — so a `/code → /gate release` line was detected-but-unfixable and hard-errored on `--apply` ("sed rewrite incomplete"). The idempotency self-test only exercised `/code → /gate fast`, hiding the asymmetry. Pattern: any detect→rewrite pair must use the SAME anchor; a detector broader than its fixer creates a flag-but-cannot-fix trap.
