# A /review fix can introduce a new bug in a different context…

A /review fix can introduce a new bug in a different context — verify portability before pinning a fix. v0.7 Phase 1's /review changed `Standard: $(dirname "$PROJECT_ROOT")/dev/CLAUDE.md` (wrong from temp-dir test harness, evaluated to `/tmp/dev/CLAUDE.md`) to `Standard: /home/rich/dev/CLAUDE.md` (correct on Rich's machine). Phase 2's /review caught that the hardcoded path is wrong on a CI runner — the path doesn't exist anywhere except Rich's box. Final fix: a public URL (`https://github.com/teelr/dev-platform/blob/main/CLAUDE.md`) — works on every machine, no localhost assumption. Pattern: when a /review fix changes how the code surfaces a system path / hostname / env-specific reference, audit the fix against *every* invocation context (local dev, test harness, CI runner, consumer adoption). Hardcoding to fix one context can break another. URLs > paths when the artifact is shared across machines.
