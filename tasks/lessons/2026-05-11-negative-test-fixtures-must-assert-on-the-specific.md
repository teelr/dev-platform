# Negative-test fixtures must assert on the SPECIFIC failure cause, not just exit…

Negative-test fixtures must assert on the SPECIFIC failure cause, not just exit nonzero. v0.7 Phase 1's first cut of `tests/taxonomy/run.sh` asserted only `expected_exit==1` on `bad-roadmap-{sprint,rprefix}.md`. Each "bad" fixture contained 1 targeted invalid line plus 2 valid lines (e.g. `v0.1: Foundation`) — meaning a future regex regression that mismatched a *valid* line would still produce exit 1 and the test would pass for the wrong reason. /review caught it. Fix: `run_roadmap_fixture` gained an optional `expected_match` 4th arg; harness now captures stderr (`2>&1`) and greps for the specific killed-prefix substring (`Sprint K:`, `R7:`). Pattern: every negative test needs two assertions — (1) it failed, AND (2) it failed for the documented reason. Exit-code-only is "did something break"; substring assertion is "did THIS break".
