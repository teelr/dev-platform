# A shared checker's hardcoded FILE PATH is the same class of silent-no-op…

A shared checker's hardcoded FILE PATH is the same class of silent-no-op risk as a hardcoded file FORMAT (see the v1.12 entry above, same day). `check_version_collision.py`/`check_spec_taxonomy.sh` both hardcoded `ROADMAP.md` at the repo root; Keystone's roadmap lives at `docs/roadmap.md` and it has no `planning.md` at all, so both checkers silently no-op'd against Keystone from day one of adoption — a confident-looking PASS/"nothing to check" that never actually checked anything, undetected until Keystone's own session investigated and filed [teelr/dev-platform#64](https://github.com/teelr/dev-platform/issues/64). Keystone's FIRST fix attempt (symlinking root `ROADMAP.md` → `docs/roadmap.md`) made it actively worse: `git show origin/main:ROADMAP.md` does not dereference symlinks, so it read the raw target-path string as file content, made every real version look "new," and produced false `COLLISION` failures against their own milestone history (reverted same night). v1.13 fixed it properly with a `ROADMAP_PATH` env var (default `ROADMAP.md`, mirroring the existing `VERSION_GUARD_REPO_SLUG` override pattern), and documented the symlink trap explicitly so no other consumer rediscovers it the hard way. Pattern: any shared checker that assumes a fixed file location for something that legitimately varies per consumer (not just format) needs the SAME "configurable, defaulting to the common case" treatment — and a `git show`-based cross-branch comparison specifically can never be worked around with a symlink; that failure mode needs an explicit override knob, not a filesystem trick.
