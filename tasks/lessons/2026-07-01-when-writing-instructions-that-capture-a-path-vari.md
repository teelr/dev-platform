# When writing instructions that capture a path/variable BEFORE a state-changing tool call…

When writing instructions that capture a path/variable BEFORE a state-changing tool call, make the capture an explicit numbered action, not a trailing parenthetical. v1.7's first cut of `/plan`'s worktree-mode step said "call `EnterWorktree`... then link deps using `${MAIN}`" and only explained *what* `MAIN` should be (`git rev-parse --show-toplevel` captured "before calling `EnterWorktree`") in a parenthetical note placed AFTER the `EnterWorktree` call in the prose. An agent following the steps in written order would capture `MAIN` too late — `git rev-parse --show-toplevel` returns the *worktree* path once `EnterWorktree` has re-rooted the session, not the main checkout — silently feeding `link-deps.sh` the wrong source directory. `/review` caught it by comparing against `/code`'s already-correct ordering (`commands/code.md:49-50`, an explicit "Record the main checkout path first" step). Fix: made `MAIN=$(...)` its own explicit action, first, before the tool call. Pattern: for any instruction where step order determines correctness (a value must be captured before a re-rooting/mutating call), state the capture as its own imperative step in execution order — never bury it in an explanatory aside after the thing it needs to precede.
