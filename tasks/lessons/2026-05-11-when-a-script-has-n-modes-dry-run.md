# When a script has N modes (dry-run/apply) × M state combinations (target-exists…

When a script has N modes (dry-run/apply) × M state combinations (target-exists / target-absent / disabled / missing-prereq), the test suite must exercise the CROSS PRODUCT, not just each axis once. v0.8 Phase 3's first cut had assertions for: dry-run with absent target (Check 6), --apply with absent (Check 7), --apply with existing (Check 8). All three PASSed and /test reported PASS. /review caught a real BUG: dry-run with existing target refused early (because the refuse-to-clobber guard didn't gate on `APPLY=1`), suppressing the entire dry-run plan. The (dry-run × existing) cell was simply missing from the matrix; each axis was covered but their intersection wasn't. Fix landed as test Check 14 + the implementation fix. Pattern: when /plan writes acceptance tests for a mode-driven script, enumerate the cross product table (rows = modes, columns = preconditions) and require every cell to have at least one assertion. Single-axis coverage gives false confidence — the bug lives in the off-diagonal cells.
