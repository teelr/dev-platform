# Regexes that extract from multi-line text files MUST be anchored to line…

Regexes that extract from multi-line text files MUST be anchored to line start (`^\s*` + `re.MULTILINE`) when the file is a structured format with comments. v0.8 Phase 4's `USES_RE` started as `r"uses:\s+teelr/dev-platform/[^@]+@(\S+)"` — unanchored. `re.search` returns the FIRST match, so a YAML comment containing `# uses: ...@v0.5` would shadow the real `uses: ...@v0.8` directive on the next line. Currently latent (source template has no such comment) but one template edit away from misclassifying every consumer. /review caught it; fix was `r"^\s*uses:\s+teelr/dev-platform/[^@]+@(\S+)"` + `re.MULTILINE`. The test fixture (`commented-uses-1` mock with the shadow comment present) was added in the same fix so the bug class can't recur silently. Pattern: when extracting from YAML / TOML / INI / Python / any commentable format, ALWAYS anchor the regex at start-of-line. Unanchored regexes treat every line uniformly, which is wrong for any format where comments and code coexist.
