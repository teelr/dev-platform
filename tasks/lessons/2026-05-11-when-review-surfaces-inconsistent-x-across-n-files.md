# When /review surfaces "inconsistent X across N files," the answer isn't always…

When /review surfaces "inconsistent X across N files," the answer isn't always "align them." Sometimes the asymmetry is deliberate and the fix is to document the rationale where readers look. v0.5 Phase 2's /review flagged inconsistent fallback-emission strategies across 4 hooks (session-start + post-tool-heartbeat have fallback echo; user-prompt + pre-tool-use are silent). Each has a defensible reason (privacy for user-prompt; pairing semantics for pre-tool-use). The fix was a "Fallback asymmetry" section in `monitoring/README.md`, NOT alignment. Pattern: when /review's QUALITY findings call out inconsistency, first ask "is the asymmetry deliberate?" — if yes, document the rationale; if no, align.
