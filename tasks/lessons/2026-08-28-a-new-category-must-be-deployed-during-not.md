# A new `scripts/install.sh` category must be DEPLOYED during `/code`, not deferred to…

A new `scripts/install.sh` category must be DEPLOYED during `/code`, not deferred to post-merge — `scripts/verify.sh`'s matching drift check runs inside `gate_fast.sh` as an always-on lift check, and `/gate fast` must pass BEFORE commit while post-merge runs AFTER it. v1.18 put `./scripts/install.sh shell` in the spec's post-merge section; the gate then failed with `live ~/.claude/ verify (drift)` and blocked the commit, because `~/.claude/profile.d/claude-tmux.sh` didn't exist yet. The failure was briefly masked by a stray deploy, which is worse than failing outright — it hid the ordering bug behind a green gate. Pattern: any Change that adds a check for a deployed artifact must also perform the deploy in the same `/code` turn. The generalization beyond install categories: if `/code` adds a verification that reads live system state, `/code` must also put that state in place.
