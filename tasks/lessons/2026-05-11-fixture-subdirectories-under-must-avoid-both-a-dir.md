# Fixture subdirectories under `tests/<suite>/fixtures/` MUST avoid both (a) directory names that collide…

Fixture subdirectories under `tests/<suite>/fixtures/` MUST avoid both (a) directory names that collide with repo-wide gitignore patterns and (b) runnable `.sh` files that the gate orchestrator could pick up as test runners. v0.8 Phase 1 hit BOTH simultaneously: spec said `tests/fleet-gate/fixtures/projects/{pass-1,...}/gate.sh`, but `.gitignore:132 projects/` is an unanchored exclude (matches `projects/` anywhere in the tree, beats the earlier `!tests/**/*.sh` re-include by rule-order); AND `scripts/gate_fast.sh`'s find walked `tests/<suite>/**/*.sh` and would have executed each mock gate as a test runner (one would fail, one would sleep 999s and hang the entire gate). Fixes: (a) rename to `mock-projects/` to dodge the gitignore; (b) extend the gate's find with `! -path "*/fixtures/*"` codifying the contract "test runners live at `tests/<suite>/*.sh` or `tests/<suite>/<test>/*.sh`, NEVER under `fixtures/`". Pattern: when designing fixture trees, (1) `git check-ignore -v` every new file before treating it as tracked, (2) ensure executable `.sh` files inside `fixtures/` are explicitly excluded by the orchestrator's auto-discovery. Both v0.6's `mock-bin/<binary>` (extension-less) and v0.8's `mock-projects/<X>/gate.sh` are valid fixture shapes ONLY because the find pattern excludes them.
