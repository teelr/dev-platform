# When promoting a script from another project, the fixtures used to test…

When promoting a script from another project, the fixtures used to test it must match the CONSUMING project's real file conventions, not the source project's. v1.11 promoted `claim_roadmap_version.py`/`check_version_collision.py` from kermit-v3 verbatim, including their regex assuming heading-form `## v<N>.<M>:` Roadmap Phase headers — kermit-v3's own convention. dev-platform's `ROADMAP.md` actually uses list-form (`- **v<N>.<M>: <Title>**`), which `check_spec_taxonomy.sh` (the project's own proven checker) has explicitly supported for both forms since v0.7. Because every test fixture in `tests/version-collision/` used heading-form content (copied from the source project's own examples), the suite passed 10/10 and both `/code`'s self-review and `/review`'s independent pass missed that the promoted regex could never match dev-platform's real `ROADMAP.md` at all — the `version-collision` CI job shipped in v1.11 silently no-op'd on every PR until caught live during post-merge dogfooding and fixed in v1.12. Pattern: when porting code between projects/repos, audit test fixtures against the DESTINATION's actual file formats, not just the source's — a fixture that only proves "the ported logic still does what it did before" can miss "the ported logic never worked here to begin with."
