# Detection patterns for "old text" must not self-referentially match documentation about that…

Detection patterns for "old text" must not self-referentially match documentation about that old text. v0.9 Phase 2's `audit-project-drift.sh` initially used `grep -qE "/code → /test\|/test → /review"` to detect old workflow chain lines. The CLAUDE.md carve-out added in the same Phase contains the sentence "Detects lines matching the old chain pattern (`/plan → /code → /test`)" — which the grep matched, falsely flagging dev-platform itself as DRIFT. Fix: require a trailing arrow after `/test` (`/code → /test →`) so the pattern only matches chain usages where `/test` is followed by another step, not documentation where `/test` ends the example. Pattern: when writing detectors for legacy strings, include enough trailing context (next token, delimiter, closing character) to distinguish actual usages from documentation about them.
