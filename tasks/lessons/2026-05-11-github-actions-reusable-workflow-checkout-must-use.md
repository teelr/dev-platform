# GitHub Actions reusable-workflow checkout MUST use `github.workflow_sha`, NOT `github.workflow_ref`. v0.7 Phase 2's…

GitHub Actions reusable-workflow checkout MUST use `github.workflow_sha`, NOT `github.workflow_ref`. v0.7 Phase 2's spec prescribed `ref: ${{ github.workflow_ref \|\| 'main' }}` for the dev-platform self-checkout inside `taxonomy-check.yml`. Per [GitHub Actions docs](https://docs.github.com/en/actions/learn-github-actions/contexts), `github.workflow_ref` returns the FULL ref-path string (`owner/repo/.github/...@refs/tags/v0.7`), which `actions/checkout`'s `ref:` cannot resolve as a git ref — invocation would fail at first consumer adoption. `github.workflow_sha` is the commit SHA the calling consumer's pinned tag resolves to. /test caught the spec bug before any consumer hit it. Pattern: for reusable workflows (`workflow_call` trigger) that need to check out their own repo, always use `github.workflow_sha`; comment why (people read `workflow_ref` and assume it's the right knob).
