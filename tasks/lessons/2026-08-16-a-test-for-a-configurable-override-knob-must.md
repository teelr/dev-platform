# A test for a configurable override knob must construct fixtures where the…

A test for a configurable override knob must construct fixtures where the override's value actually changes the outcome — otherwise a silently-ignored override still passes. v1.14's first cut of the `DOCS_ONLY_BASE_REF` override test created `baseline` and `feature` both pointing at the exact same commit, then asserted the detector, pointed at `baseline`, correctly found a docs-only diff. It would have passed identically even if the code hardcoded `main` and never read the override at all, because `main` and `baseline` were indistinguishable at that commit. Caught at Step 6 self-review, not by the test itself. Fix: made `baseline` diverge from `main` with its own non-doc commit before branching `feature` off it, so diffing against the default `main` (bug case) and against `baseline` (correct case) produce different, discriminable results — verified live by temporarily hardcoding `main` into a scratch copy of the detector and confirming exactly that one assertion flips to FAIL. Pattern: same family as the "negative-test fixtures must assert on the SPECIFIC failure cause" (2026-05-11) and "mock failure-injection counter must guard on an explicit threshold" (2026-08-12) lessons — any test of a knob (override, flag, threshold) needs a fixture where the DEFAULT and the OVERRIDDEN path provably diverge, or the test only proves the happy path runs, not that the knob does anything.
