# The gate's bash-syntax loop does NOT walk `shell/`. `scripts/gate_fast.sh` syntax-checks `*.sh` only…

The gate's bash-syntax loop does NOT walk `shell/`. `scripts/gate_fast.sh` syntax-checks `*.sh` only under `scripts/`, `hooks/`, `scaffolding/*/scripts/`, and `tests/` — never `shell/`. So `shell/git-hooks/*` (v1.2) and `shell/worktree/*.sh` (v1.4) get ZERO syntax coverage from the gate unless their own test suite runs `bash -n` on them. v1.4's `tests/worktree/run.sh` opens with two `bash -n` assertions on `link-deps.sh` + `gate-lock.sh` for exactly this reason. Pattern: any executable/sourceable script added under `shell/` must be `bash -n`'d by a `tests/<suite>/` runner — the orchestrator's syntax sweep won't catch it. (Don't widen the gate's `find` without intent; the per-suite assertion is the established fix.)
