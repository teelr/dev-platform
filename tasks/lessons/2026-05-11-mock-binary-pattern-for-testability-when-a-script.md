# Mock-binary pattern for testability — when a script depends on an external…

Mock-binary pattern for testability — when a script depends on an external command (`code`, `python`, `docker`), the round-trip tests need to exercise the command's behavior without touching the live system. v0.6 introduced `tests/vscode/fixtures/mock-bin/code` — an extension-less Bash script that mimics `code --list-extensions` and `code --install-extension` via a `MOCK_STATE_FILE` env var. The test runner sets `PATH="${MOCK_BIN}:${PATH}"` so the mock takes precedence over the real binary. Same pattern works for any sufficiently-narrow CLI surface. Prerequisite: the script under test must accept a `--file <path>` (or similar) override so it doesn't hardcode-write to the live tracked file. v0.6 added that flag to `sync-vscode.sh` as part of the /review fix. Pattern: when adding a CLI script that touches external state, build in a state-file override flag from the start so future mock-based testing is cheap.
