# String args that drive comparison logic MUST be validated at the argparse…

String args that drive comparison logic MUST be validated at the argparse boundary; silent degradation on malformed input is the failure mode worth designing out. v0.8 Phase 4's `--latest <vX.Y>` flag accepted any string — so `--latest 0.7` (missing the `v` prefix) silently degraded every project to "up-to-date" because `parse_semver_minor` returned `None` and `classify` short-circuited. The user sees "everything fine" when the comparison axis was actually broken. Fix: validate `--latest` against `SEMVER_RE` BEFORE the fan-out; exit 2 with `"ERROR: --latest must be a semver tag (vX.Y or vX.Y.Z); got '<value>'"`. Pattern: any CLI arg whose value flows into a parser, regex, or comparison should be format-validated at the argparse boundary. Fail-loud > fail-silent. The cost of a 5-line validation is negligible; the cost of "looks fine but is wrong" is the user trusting the report.
