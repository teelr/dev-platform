# R4a spec missed two implicit prerequisites that surfaced at /code time: (a)…

R4a spec missed two implicit prerequisites that surfaced at /code time: (a) `.gitignore` allow-list extension for template file types (.ts, .tsx, .py, .go, .toml, .mod, .gitkeep, etc.) plus subdirectory re-includes (`!scaffolding/**/`) — without these, scaffolded template content was silently gitignored; (b) `new-project.sh` `find` pattern initially missed `.gitignore` (no extension), so the go-service template's `.gitignore` placeholder didn't get substituted. Both caught + fixed at /code time, but the spec assumed they'd "just work." Class of issue: spec writers (including /plan agents) routinely under-spec gitignore + sed-pattern coverage when introducing new file types. Going forward: any /plan that adds a new file type or a new top-level dir MUST explicitly include a Change for the gitignore allow-list update AND verify the substitution coverage.
