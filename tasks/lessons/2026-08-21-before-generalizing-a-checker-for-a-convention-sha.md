# Before generalizing a checker for a convention "shared" across N consumer projects…

Before generalizing a checker for a convention "shared" across N consumer projects, verify each project's actual file live — don't assume uniformity from the one project that filed the report. v1.17's issue described `tasks/HARNESS_HANDOFF_QUEUE.md`'s "Ask #" numbering and `tasks/lessons.md`'s "L#" numbering as conventions kermit-v3/Keystone/kermit-pa all share; grepping all three real files during planning found otherwise — kermit-v3 has 5 independently-numbered `#`-headed queue tables, Keystone has 4 (missing kermit-v3's specific Ask table), and kermit-pa's queue file has ZERO `#`-headed tables at all (a completely different Date/Feature/Migration-plan column shape, no numeric column) — only the lessons-L# convention is genuinely shared by all three. Had the checker been written to kermit-v3's shape alone (hardcoded column layout, or a whole-file duplicate scan instead of table-scoped), it would have either silently no-op'd on kermit-pa or, worse, false-flagged kermit-v3's own file: raw values `#39` and `#37` each legitimately repeat there today, in two different independently-numbered tables. Pattern: same family as the v1.11 "fixtures must match the CONSUMING project's real conventions, not the source project's" lesson (2026-08-12), one layer earlier — verify the SET of consumers' shapes before writing the generic scan, not just the fixtures that test it.
