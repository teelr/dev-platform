# When you add a check that enforces the PRESENCE of X, seed…

When you add a check that enforces the PRESENCE of X, seed X into whatever bootstraps new instances — or every newly-created instance starts in violation. v1.8 taught `audit-project-drift.sh` to flag a `CLAUDE.md` missing the workflow chain (`MISSING_CHAIN`), but the scaffolding templates (`scaffolding/*/CLAUDE.md`) and the reference `docs/PROJECT_CLAUDE_TEMPLATE.md` didn't carry the chain — so every project scaffolded via `new-project.sh` would have read `MISSING_CHAIN` on its first audit. v1.9 seeded a `## Development Workflow` section (canonical chain + gate note) into all four templates and added an end-to-end scaffold→audit-CLEAN guard. Note the "don't duplicate rules from dev/CLAUDE.md" template guidance is NOT violated: the one-line chain is a required project-level *declaration* the audit checks for, not a duplicated rule body (documented via an HTML comment in the doc template). Pattern: a presence-check and the bootstrap path that creates new instances are a matched pair — ship them together, or the check indicts its own scaffolding.
