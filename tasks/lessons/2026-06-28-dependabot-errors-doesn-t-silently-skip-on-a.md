# Dependabot ERRORS (doesn't silently skip) on a dependency it can't resolve —…

Dependabot ERRORS (doesn't silently skip) on a dependency it can't resolve — so a locally-installed dep must be explicitly `ignore`d in the consumer config. v1.5's Dependabot consumer template assumed the `pip` block would just track everything; PA's adoption (PR #127) found `kermit-harness` is a local editable install (not on PyPI), and the same is true for Keystone (vendored wheel) — not on PyPI for ANY consumer. Without an `ignore`, the pip block fails on it. Fix: the template now documents the locally-installed-dep caveat in its header + ships a commented `ignore: kermit-harness` example in the pip block; its pin stays a manual bump. Pattern: when shipping a config template that auto-discovers dependencies, account for the deps that CAN'T be discovered (local/editable/vendored/private-index) — the tool fails loud on them, so the template must pre-empt with an ignore example, not assume the happy path.
