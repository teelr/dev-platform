# A worktree session's command guard refuses variable-built paths, not outside paths

`/plan` and `/code` both prescribed `bash "${HOME}/.claude/worktree/link-deps.sh" "${MAIN}" "$(pwd)"`, and a worktree-isolated session refuses it with "too complex to verify that it stays inside the worktree" — so the dependency-linking step silently never ran. I first assumed the refusal was about passing the main checkout as an argument, and said so in a PR. It wasn't: `bash /home/rich/.claude/.../link-deps.sh /home/rich/dev .` runs fine, and so does the `~` form with both arguments. Narrowing it took three one-line probes — no args, literal path, tilde — and the trigger is the `${HOME}` expansion alone, because the guard analyses the command statically and cannot resolve a variable.

Write `~/...` in any command a worktree session is expected to run. The guard is also strict about compound commands generally — a heredoc whose *body* contains `git rev-parse`, or a `python3 - <<PY` block followed by a chained check, gets refused too; use one plain command per call, or the Edit/Write tools. And when a guard refuses something, bisect the command rather than believing the first plausible story about which part offended it.

**Two more instances, same root cause, same day (v1.27).** `/plan` Step 2 prescribed `[[ -n "${TMUX:-}" ]] && tmux rename-window "<slug>"`, and `/merge` Step 4 prescribed an `if [[ "$(git rev-parse ...)" == "true" && ... ]]` worktree detection. Both refused, both silent: the window rename never happened, and the merge one left `IN_WORKTREE=0` — sending the merge down the branch-mode path that `commands/merge.md` itself documents as failing the entire `gh pr merge`. A guard refusal that silently selects the wrong branch is worse than a loud error.

**The precise trigger, established by probe.** Compound alone is fine (`echo a && echo b` runs; so does `test -f .claude/worktree-deps && echo A || echo B`). A variable alone is fine (`echo "TMUX=${TMUX:-unset}"` runs). It is the **combination** — a compound command that also carries a variable expansion or command substitution — that gets refused. My first correction here overstated it as "no compound commands," which would have made every future command block needlessly awkward; four one-line probes found the real boundary. Bisect before writing the rule, not just before believing the error message.

**What the second and third hits teach that the first did not:** the link-deps fix was local to its own script, so it left every other prescribed command in `commands/*.md` unexamined. When a guard refuses one prescribed command, sweep them all — `grep -n '&&\|||\|\${\|\$(' commands/*.md`, then check each hit for the combination. Promoted to a rule in `CLAUDE.md` at this third recurrence.
