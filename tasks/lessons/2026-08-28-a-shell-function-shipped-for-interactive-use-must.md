# A shell function shipped for interactive use MUST be tested in an…

A shell function shipped for interactive use MUST be tested in an INTERACTIVE shell (`bash -i <script>`), not just `bash -c`. v1.18's `cc` passed all 18 assertions and CI, then failed on the user's first real login shell: `~/.bashrc` already had `alias cc='claude repl'`, and bash expands aliases at PARSE time, so `cc() {` was a syntax error and the alias silently won — the function was never defined. `bash -c` does not expand aliases, so every test was blind to it. Fix: `unalias cc 2>/dev/null || true` as its own command before the definition (same parse unit is too late), plus a `bash -i` regression assertion verified to FAIL when the fix is reverted. Pattern: match the test harness's shell mode to the deployment's shell mode — interactive features (aliases, `shopt` expand_aliases, prompt hooks, job control) are invisible to non-interactive test shells. Corollary: when shipping a name, grep the deployment target for an existing binding first.
