Redirection SCOPE bit twice in one change, both times silently. (1) `exec 9>"$lf" 2>/dev/null` — `exec` with no command applies EVERY redirection to the shell permanently, so that `2>/dev/null` silenced the shell's stderr for the rest of the run and swallowed the very messages the change existed to print; the lock worked, the announcements vanished. (2) In the test, `out="$( cmd1 && cmd2 2>&1 )"` attaches the redirect to `cmd2` only, so stderr never entered the capture — which made a "must be silent" assertion pass vacuously, worse than failing. Both need the redirect on the whole group: `exec 9>"$lf"` after a scoped probe, and `"$( { ...; } 2>&1 )"`. When a message you just added does not appear, suspect the redirection before the logic.
